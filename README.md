# DeepSeek Harness Atlas

一张可以把玩的 3D 架构地图，外加 22 篇技术档案和一篇长文，讲的是 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 这套 agent harness 的架构。

中英双语。

## 这是什么

DeepSeek Harness 有 219 个包、19.8 万行源码，而它的「主循环」只有 1,643 行。这个反差本身就说明了它的架构取向——所以与其写一份索引式的文档，不如画一张地图。

地图上：

- **22 块地按关注点分成七片区域**，不是按目录结构
- **地形高度是真实源码行数**，最高的那块 8.2 万行是浏览器界面，最矮的 1,643 行是主循环
- **35 条道路是真实的依赖关系**，分四类：调用服务、拦截事件、注册贡献、接缝实现
- 核心区排成一圈围着主循环，因为围着它的那几样正是它声明注入的服务——空间关系就是代码里的依赖关系

导航是两级的：总览看板块之间的通道有多密，点进某片才看具体地块和它们之间谁调谁。点任意一块地，右侧抽屉直接展开完整技术档案，可全屏。

海里立着一座灯塔，指向那篇架构长文。

## 内容

- **22 篇技术档案**，每篇 6–7 节正文加关键机制、可迁移经验、代价与限制、代码索引
- **1 篇架构长文**，13 节，含 3 张手绘 SVG 图
- 中英双语各一份，合计约 33 万字

写作上有一条硬约束：**正文里不出现任何函数名、类名、文件路径**，全部收进右侧代码索引。读者不一定看过这个仓库的代码，记不住那些上下文。`pnpm check:prose` 会持续守住这条线。

## 跑起来

```bash
pnpm install
pnpm dev
```

打开 http://localhost:3000 ，会跳到 `/zh`。英文在 `/en`。

```bash
pnpm build        # 生产构建，四条路由全部静态预渲染
pnpm check:prose  # 正文体检：扫代码痕迹、空词、手册腔
```

## 技术栈

Next.js 16（App Router + Turbopack）· React 19 · Tailwind 4 · Three.js（react-three-fiber / drei）

3D 部分是卡通着色加墨线描边的绘本风格：区域轮廓是椭圆叠正弦扰动算出来的有机形状，海面是程序化生成的手绘波纹贴图，岛的轮廓、房子的歪斜角度、装饰物位置全部走确定性种子，所以每次刷新地图长得一模一样。

## 目录

```
src/
  app/[locale]/          语言路由：/zh /en，各含地图页与长文页
  components/atlas/      3D 场景：地块、区域、道路、灯塔、相机
  components/Prose.tsx   极简行内标记渲染
  content/
    map.ts               区域、地块、道路数据（双语）
    i18n.ts              语言定义与界面词条
    archives/{zh,en}/    22 篇技术档案
    article/             长文（中英各一份）
scripts/check-prose.mjs  正文体检
```

## 数据从哪来

地块的源码行数是实测的，道路只收录在源码或精读报告里确认过的依赖关系，不收「理论上应该有」的连线。长文里那些批评性的结论——比如 26 条能力接缝里 15 条从未换过实现、存在一个生成的依赖图看不见的循环依赖——都是逐条跑命令验证过的。

档案里标注了证据强度：哪些是逐行读过实现，哪些只依据文档。
